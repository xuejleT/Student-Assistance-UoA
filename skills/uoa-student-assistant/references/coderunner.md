# CodeRunner

## Find and verify the course

1. In the matching Canvas course, look for CodeRunner links in Modules, Assignments, Pages and Announcements. Prefer the course's current link. The official [CodeRunner Main](https://coderunner.auckland.ac.nz/) Moodle site is a fallback. Its public course search can help match the code, year and teaching period. The computer science department's 2015 guide describes an older `/moodle/` route and example attempt settings. Use current course evidence for both navigation and rules. [2015 guide](https://www.cs.auckland.ac.nz/compsci230s2c/assignments/How%20to%20Use%20Code%20Runner.pdf)
2. Reuse the browser session when possible. If the login page shows **Login via UPI**, follow the observed official route and hand off credentials or MFA on the school's sign-in page. Verify CodeRunner independently by opening the requested course in **My courses** or its student course view. A public listing establishes course discovery only. [Connection workflow](connection.md)
3. Use the course section, activity information page or Moodle Calendar to read visible instructions and existing feedback. Open an activity link only when its destination is understood. An observed Moodle `mod/quiz/view.php` course activity link can lead to the information page. Calendar actions may say **Go to activity** or **Attempt quiz now**. Use a known information link instead of an ambiguous button. If opening the available link could create an attempt, stay with Canvas/course/calendar evidence and report the limit.

## Collect evidence for planning

- Record the course code, year/term, activity title, stable course or activity link, source title and check time. Record displayed practice or grade status, time limit, attempts remaining or allowed, penalties, available feedback, and AI instructions only when relevant and visible. Mark unknown fields explicitly.
- Keep opens, due, closes and individual extension dates distinct. Moodle Calendar's **closes** entry is evidence of a close time. Preserve the date's original meaning and convert to Pacific/Auckland only when the source timezone is known. A date alone stays date-only.
- Link a Canvas assignment and CodeRunner activity as one planning item only when a current course link or explicit instruction connects them. Keep both source links and all date labels, even when the names match or dates differ. Put uncertain items in a follow-up list.
- Report separate states for course listed, login required, course accessible, activity details verified, and feedback verified. If a graded activity already has released feedback, read it only when the request calls for it. Keep attempt identifiers, responses and personal marks out of shared logs and release files. Use a stable course/activity link instead of session, attempt or authorization URLs.

## Provide help within the activity rules

- Read the current Canvas and CodeRunner instructions before helping on an activity. Record the controlling source. The University distinguishes controlled assessments with restricted AI use from uncontrolled assessments. Apply the course's stated scope, including any acknowledgement requirements. If rules are missing, ambiguous or conflicting, help with scheduling and independently authored exercises on the concepts while the student verifies the rules. [University advice on AI in assessment](https://www.auckland.ac.nz/en/students/forms-policies-and-guidelines/student-policies-and-guidelines/academic-integrity-copyright/advice-for-student-on-using-ai.html)
- For practice that permits assistance, identify the required language and whether the task expects a whole program, class or function. Work through the student's approach, inspect visible feedback and design local tests with clearly stated assumptions. Label local results separately from CodeRunner feedback. Use only published or user-supplied test cases and assistant-authored cases. Treat hidden grader behavior as unknown.
- Before **Attempt**, **Check**, **Run**, **Finish attempt** or **Submit**, establish the actual effect from the current UI and instructions. Some checks record an answer, consume an attempt or apply a penalty. Course permission for AI help and the user's authorization for the specific browser action are separate requirements. Scope authorization to the actual activity and effect. After an authorized action, verify the visible result or existing attempt status before any retry. [CodeRunner project documentation](https://coderunner.org.nz/)
