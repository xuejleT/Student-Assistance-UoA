# Courses and enrolment

Use the academic year and exact term the user requests. Keep the programme regulations year separate from the year and term of the proposed enrolment. If the target term is missing and changes the plan, ask for it. Verify programme, major or specialisation and the applicable regulations from the current SSO record or user-provided documentation when available.

## Research and planning

1. Read My Programme Requirements and the relevant approved history from Student Services Online (SSO). If the homepage tile leaves a blank panel, use Enrol > Add Classes with > My Programme Requirements and select the requested term. Wait for the requirement rows. A message that course search by requirements is unavailable can coexist with a readable report. Record the displayed requirement status and check which courses are completed or still in progress before making a final eligibility claim. Use the [academic records workflow](academic-records.md) for final grades, repeated attempts and GPA. Treat approved transfer credit, substitutions, conjoint allocation and pending results as separate cases. A course contributes to multiple requirement blocks only where the rules or SSO report allow it.
2. Match the official Curriculum Catalogue and programme regulations to the applicable cohort. If the programme report is missing or SSO access is unavailable, complete a conditional plan from public rules and any records the student chooses to provide. Mark unverified requirements and prerequisites. Refer unresolved programme-specific interpretations to Student Hubs or the relevant faculty with the exact requirement and course in question.
3. Match each candidate to its intended offering year, term, campus and delivery mode. Record code, title, points, requirement served, prerequisites, corequisites, restrictions and linked class components. Use passed results or an explicitly approved equivalent to clear prerequisites. Mark in-progress and pending grades as conditional. Check any double-term A/B pair, published Class Notes, reserved seats, waitlist, holds and consent requirements. Public records can establish rules and published offerings, while individual eligibility and successful enrolment require SSO evidence.
4. Build the primary timetable and a fallback. Preserve existing enrolments and the student's stated hard constraints. Rank alternatives by verified degree progress, workable sequencing, schedule and workload preferences. For each fallback explain which course or stream changes, why, and which enrolment conditions remain. If evidence cannot support a usable fallback, identify the constraint or missing evidence that would make one possible.

Curriculum Catalogue search may default to a future year, and public page extraction may include hidden filter values. Use the visible selected year and record version. Distinguish a course's effective term and normal offering pattern from an actual scheduled class. Use archived 2020–2025 outlines only for the relevant historical offering and label them accordingly.

## Check timetable conflicts

Use Class Search or Timetable Planner for the proposed enrolment and My Timetable for already-enrolled meetings. For every required lecture, tutorial, lab, workshop or other timed component, preserve the course and class number, linked stream, campus or mode, weekday, start/end, first/last meeting dates and known exceptions. Check required components within each course and across courses. Asynchronous sessions need an evidenced flexible designation. Flag a blank or TBA meeting as unchecked.

Compare actual occurrence dates, including alternating weeks, block teaching, holidays and make-up meetings where published. For two weekly sessions, a shared weekday alone is insufficient. Look for a shared occurrence date on both schedules and a nonzero overlap of their time intervals. Back-to-back sessions do not overlap, but flag transitions between campuses or delivery modes when the gap may be impractical. If dates or recurrence are incomplete, describe the possible overlap and the missing evidence. Apply the [calendar workflow](calendar.md) for timezone handling, personal exam dates and the current enrolment timetable.

If guest Class Search redirects to help or SSO is unavailable, use the public Curriculum Catalogue to verify scheduled offerings and rules. Mark both proposed timetables as provisional until their actual required streams and meeting times are confirmed. [Class Search help](https://uoa.custhelp.com/app/answers/detail/a_id/17293)

Return the requested year and term, regulations year, verified versus provisional requirements, and a comparison of the plans. Include course points, requirement impact, required stream choices, specific clash dates or unresolved checks, and source links with check times. Add a next step for each blocker, such as checking the class notes or confirming a named prerequisite with Student Hubs.

## SSO actions

Observed live: Enrol opens Current Enrolment Status. Expand the side panel, expand Add Classes with, then select Class Search. Choose the actual year/term. Content can update after an initial Processing indicator; inspect the loaded form before acting. A blank loading panel is not absent access.

Observed homepage tiles: Enrol, Manage Classes, Course Catalogue, My Programme Requirements and My Class Timetable. Inspect current UI instead of hardcoding PeopleSoft session URLs or hidden actions.

Official sequence is intended term > select classes using Timetable Planner/Class Search/My Programme Requirements/class number > Add to Cart > review cart/Calendar View > Validate > inspect prerequisite/restriction/hold errors > read Class Notes > review terms/choices > Enrol.

Setup does not authorize adding courses or changing the cart. A specific prepare-cart request authorizes only the stated choices; preserve unrelated entries. Read-only validation of an existing cart is appropriate only within task scope and when the actual control has no enrolment effect. Do not generate What-if Reports or concession applications merely because their tiles are present.

Before final enrol/swap/drop, show term, classes/components, before/after set and known fee/deadline effects. For additions, deletions or withdrawals verify the course-specific deadline in SSO, especially for nonstandard dates and double-term courses. Label general term dates as indicative if the official course deadline is inaccessible. Honor specific authorization and host confirmation rules. Binding terms require action-time confirmation/user handoff as the host requires. Do not select an unrequested payment method or change bank/personal details.

Verify each actual enrolled/dropped/waitlisted/error result. Cart presence and validation are not enrolment. After timeouts inspect existing results before retrying. Report partial success per course and do not substitute unrequested alternatives.
